# AGENT.MD — Протокол мониторинга и прогресса sub-агентов

> Используй этот файл как обязательный чек-лист при планировании и запуске любой multi-agent задачи. Он гарантирует visibility: вы всегда видите, что происходит, и знаете, если агент завис.

---

## 1. Heartbeat-файл (индикатор жизни агента)

Каждый агент ДОЛЖЕН вести heartbeat-лог. Если файл не обновлялся более 5 минут — агент, скорее всего, мёртв.

### 1.1 Шаблон heartbeat

```python
import datetime

HEARTBEAT_FILE = "/mnt/agents/output/progress_heartbeat.log"

def heartbeat(stage: str, detail: str = ""):
    with open(HEARTBEAT_FILE, "a") as f:
        ts = datetime.datetime.now().isoformat()
        f.write(f"[{ts}] {stage}: {detail}\n")
        f.flush()

# Примеры вызовов:
heartbeat("start", "Начало обработки запроса XYZ")
heartbeat("research", "Собрано 15 из 50 источников")
heartbeat("research", "Собрано 35 из 50 источников")
heartbeat("draft", "Начало написания главы 2")
heartbeat("complete", "Задача завершена, файлы: result.md")
```

### 1.2 Правила heartbeat

| Правило | Значение |
|---------|----------|
| Частота | Каждые 2–3 минуты активной работы |
| Обязательные точки | Старт, смена этапа, 25/50/75% прогресса, завершение |
| Формат | `[ISO-timestamp] stage: detail` |
| Файл | Всегда `/mnt/agents/output/progress_heartbeat.log` |

## 2. Checkpoint-артефакты (промежуточные результаты)

НЕ ждите одного финального файла. Каждый этап — отдельный файл.

### 2.1 Структура чекпоинтов

```
/mnt/agents/output/
├── heartbeat.log                      # Живость агента
├── checkpoint_01_<stage>_raw.md       # Сырые данные
├── checkpoint_02_<stage>_processed.md # Обработанные данные
├── checkpoint_03_<stage>_draft.md     # Черновик
├── checkpoint_04_<stage>_reviewed.md  # После ревью
└── final_<name>.md                    # Финальная сборка
```

### 2.2 Принципы checkpoint

- **Один этап = один файл.** Агент завершил этап — сразу записал файл.
- **Файлы атомарны.** Можно прочитать промежуточный результат без ожидания финала.
- **Версионирование.** Каждый checkpoint содержит шапку с timestamp и статусом.

### 2.3 Шапка каждого checkpoint-файла

```markdown
---
checkpoint: 03
created: 2026-05-17T14:32:10
status: in_progress | completed | blocked
stage: draft_chapter_2
progress: 40%
next_stage: review_chapter_2
---

# Содержимое checkpoint...
```

## 3. TODO-лист: гранулярность и обновление

### 3.1 Правила декомпозиции

- **Максимум 10 минут на задачу.** Если задача дольше — разбейте на подзадачи.
- **Максимум 7 задач в одном todo_write.** Если больше — выделите под-этап.
- **Конкретика вместо абстракций.**
  - ❌ "Сделать исследование"
  - ✅ "Найти 10 источников по API X за 2024–2025"

### 3.2 Статусы и transitions

```
pending → in_progress → completed
              ↓
           blocked (обязательно с пояснением)
```

### 3.3 Обязательные обновления todo

| Событие | Действие |
|---------|----------|
| Агент стартует | `todo_write` — отметить задачу `in_progress` |
| Прогресс 50% | Обновить todo с детализацией |
| Блокер | Сразу `todo_write` со статусом + описание проблемы |
| Этап завершён | `todo_write` — `completed` + следующая задача `in_progress` |

## 4. Таймауты и fallback-стратегии

Каждая задача агента ДОЛЖНА содержать Plan B.

### 4.1 Шаблон fallback-инструкции (в prompt агента)

```
Если одно из условий ниже истинно:
  - Операция занимает >10 минут
  - 3 последовательные ошибки
  - Результат пустой после 5 попыток

ТО:
  1. Запиши в /mnt/agents/output/fallback_<stage>.md:
     - Что не удалось
     - Почему (конкретная ошибка)
     - Какие данные удалось собрать до падения
  2. Пометь todo-задачу как blocked
  3. Перейди к следующему этапу с имеющимися данными
```

### 4.2 Таблица таймаутов по типу задачи

| Тип задачи | Таймаут | Действие при превышении |
|-----------|---------|------------------------|
| Web-поиск (1 query) | 2 мин | Пропустить, перейти к следующему |
| Браузерная навигация | 3 мин | Перезагрузить страницу |
| Запись в файл | 30 сек | Retry с пересозданием файла |
| Длительная обработка данных | 10 мин | Чекпоинт + продолжение |
| Полный pipeline агента | 30 мин | Принудительный fallback |

## 5. Мониторинг browser-задач

При работе с браузером агент ОБЯЗАН делать скриншоты на ключевых этапах.

### 5.1 Обязательные скриншоты

| Этап | Действие |
|------|----------|
| Страница загружена | Скриншот для проверки рендеринга |
| После скролла | Скриншот для проверки динамической подгрузки |
| Перед кликом | Скриншот для проверки целевого элемента |
| После действия | Скриншот для проверки результата |
| Ошибка/блокер | Скриншот проблемной страницы |

### 5.2 Сохранение скриншотов

```python
# Формат имени
screenshot_path = f"/mnt/agents/output/screenshot_{stage}_{timestamp}.png"

# Пример
browser_screenshot(download_screenshot_path="/mnt/agents/output/screenshot_search_results_143210.png")
```

### 6.2 Что НЕ удалось
- [ ] Поиск по API Y — таймаут после 3 попыток

### 6.3 Созданные файлы
| Файл | Описание | Размер |
|------|----------|--------|
| checkpoint_01_raw.md | Сырые данные | 45 KB |
| checkpoint_02_draft.md | Черновик | 23 KB |

### 6.4 Рекомендации по следующему шагу
1. Использовать checkpoint_02_draft.md как базу
2. Дополнить раздел Y данными из альтернативного источника Z
3. Перейти к этапу review

## 8. Быстрый аудит: как проверить статус прямо сейчас

### 8.1 Команды для проверки

```bash
# 1. Проверить heartbeat (последние 10 записей)
tail -10 /mnt/agents/output/progress_heartbeat.log

# 2. Узнать, какие чекпоинты созданы
ls -la /mnt/agents/output/checkpoint_*

# 3. Проверить размеры файлов (рост = прогресс)
watch -n 10 "ls -la /mnt/agents/output/"

# 4. Посмотреть текущий todo-лист
# (через read_file на todo-файл, если сохраняется отдельно)

# 5. Проверить скриншоты (для browser-задач)
ls -la /mnt/agents/output/screenshot_*
```

### 8.2 Признаки "зависшего" агента

| Признак | Вероятная причина | Действие |
|---------|------------------|----------|
| Heartbeat не обновлялся >5 мин | Агент упал или в бесконечном цикле | Перезапустить с последнего checkpoint |
| Checkpoint-файл пустой или не создан | Ошибка записи | Проверить права доступа, retry |
| Скриншоты не появляются при browser-работе | Браузер завис на странице | Перезапустить браузер-сессию |
| Todo статус in_progress >15 мин без обновления | Агент застрял на сложной задаче | Проверить heartbeat, при необходимости прервать |

## 9. Пример: полный pipeline с мониторингом

```
[Оркестратор]
    │ todo_write — публикует план
    │
    ▼
[Агент-1: Исследование]
    │ heartbeat("start")
    │ checkpoint_01_raw.md — записан
    │ heartbeat("research", "25%")
    │ checkpoint_02_processed.md — записан
    │ heartbeat("research", "75%")
    │ checkpoint_03_analyzed.md — записан
    │ heartbeat("complete")
    │ → финальный отчёт
    │
    ▼
[Оркестратор]
    │ Читает checkpoint_03_analyzed.md
    │ todo_write — обновляет статусы
    │
    ▼
[Агент-2: Написание]
    │ heartbeat("start")
    │ checkpoint_04_draft.md — записан
    │ heartbeat("draft", "50%")
    │ checkpoint_05_reviewed.md — записан
    │ heartbeat("complete")
    │ → финальный отчёт
    │
    ▼
[Финальная сборка]
```

## 10. Анти-паттерны (чего НЕ делать)

| Анти-паттерн | Почему плохо | Что делать вместо |
|-------------|-------------|-------------------|
| Один огромный файл на весь pipeline | Не видно прогресса пока не завершится | Checkpoint-файлы на каждом этапе |
| Нет heartbeat | Не понятно, жив ли агент | heartbeat каждые 2–3 мин |
| "Сделать исследование" в todo | Слишком абстрактно, нет visibility | Разбить на конкретные шаги |
| Нет fallback-инструкций | Агент падает и тишина | Всегда описывать Plan B в prompt |
| Не обновлять todo по ходу | Статус устаревает | Обновлять todo при каждой смене статуса |
