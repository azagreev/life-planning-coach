## Consistency Issues

### 🔴 Критическое: USER_GUIDE_DRIVE.md противоречит SKILL.md по структуре wiki
**Где:** `references/USER_GUIDE_DRIVE.md` строки 63–69 vs `SKILL.md` строки 256–274.

USER_GUIDE_DRIVE.md показывает пользователю **плоскую структуру из 4 файлов**:
```
📁 Life Planning Coach Wiki
├── 📊 Dashboard — Обзор прогресса.md
├── 🎯 Goals — Цели.md
├── 💡 Insights — Инсайты и озарения.md
└── 📋 Wheel of Life — Колесо жизни.md
```

В то время как SKILL.md инструктирует Claude создавать **глубокую иерархию**:
```
Life Planning Coach Wiki/
├── 00_Raw/
├── 01_Wiki/
│   ├── Hot_Cache.md
│   ├── Index.md
│   ├── Concepts/
│   ├── Frameworks/
│   ├── User_Progress/
│   ├── Decisions/
│   └── Sources/
├── 02_Instructions/CLAUDE.md
├── 03_Dashboard/Progress_Dashboard.md
├── 04_References/
├── 05_Archive/
├── README.md
└── CHANGELOG.md
```

**Влияние:** Пользователь, прочитавший гайд, будет в замешательстве, когда увидит реальную структуру. Файлы в гайде названы по-русски с эмодзи (`🎯 Goals — Цели.md`), тогда как SKILL.md использует английские технические названия (`Progress_Dashboard.md`, `Hot_Cache.md`). Это подрывает доверие и создаёт friction.

**Рекомендация:** Привести USER_GUIDE_DRIVE.md в соответствие с SKILL.md. Показать пользователю реальную структуру папок с понятными описаниями. Файлы можно переименовать в более дружелюбные названия (или добавить user-friendly aliases в README wiki).

### 🟡 Среднее: `requires_mcp` в заголовке SKILL.md противоречит README
**Где:** `SKILL.md` строка 19 vs `README.md` строки 58, 282.

SKILL.md заголовок: `requires_mcp: "google-calendar (required), google-drive (optional for wiki persistence)"`
README.md: «Google-аккаунт — опционально (для календаря и автосохранения в Drive)»

Если google-calendar помечен как `required` в метаданных, Claude.ai **может отказать в загрузке скилла** для пользователей без подключённого Calendar MCP, несмотря на то что тело скилла gracefully degrades без календаря. README врёт пользователю, что календарь опционален, тогда как метаданные говорят обратное.

**Рекомендация:** Изменить заголовок на `requires_mcp: "google-drive (optional for wiki persistence)"` или уточнить в README, что Calendar MCP рекомендуется, но скилл работает и без него.

Index.md упомянут в дереве как «оглавление», но в разделе шаблонов отсутствует. Это нарушает AC-3.2.

## Edge Case Analysis

### Edge Case 1: Пользователь имеет данные в Memory И подключён Drive
**Сценарий:** Пользователь работал в режиме Memory, затем подключил Drive. При следующем чате Claude прочитает Hot_Cache (из Drive) и увидит данные в Memory. Что если данные конфликтуют?

**Найдено:** SKILL.md **не адресует разрешение конфликтов**. Нет инструкции вида «если Memory и Hot_Cache расходятся — приоритет у Hot_Cache» или «синхронизируй и обнови оба источника».

**Риск:** Claude может дать противоречивый emotional summary или проигнорировать свежие данные из Memory.

**Рекомендация:** Добавить одно предложение в протокол старта: «Если данные в Memory и Hot_Cache расходятся — приоритет у более свежего источника. Обнови Hot_Cache, включив информацию из Memory.»

### Edge Case 2: Пользователь удалил папку wiki, но Drive подключён
**Сценарий:** Пользователь удалил папку `Life Planning Coach Wiki` вручную через drive.google.com. Drive connector при этом остаётся активным.

**Найдено:** SKILL.md не покрывает этот сценарий явно. Graceful degradation срабатывает при «Google Drive недоступен», но удалённая папка — это не недоступность Drive, а 404-ошибка при чтении файлов.

USER_GUIDE_DRIVE.md (строка 121) утверждает: «Если удалите папку, навык просто создаст новую при следующей сессии.» Но SKILL.md не содержит этой инструкции для Claude.

**Риск:** Claude получит ошибку при попытке чтения Hot_Cache.md и может запаниковать или выдать техническое сообщение об ошибке.

**Рекомендация:** Добавить в Graceful Degradation: «Если папка wiki не найдена (удалена пользователем) — пересоздать всю структуру с нуля.»

### Edge Case 3: Сессия очень короткая (< 5 минут)
**Сценарий:** Пользователь зашёл, сказал «спасибо, до свидания» через 2 минуты.

**Найдено:** End-of-Session Protocol (строки 242–248) **не имеет условной логики** по длительности сессии. Даже для 2-минутной сессии Claude выполнит: emotional summary, обновление Memory, предложение Drive (если не предлагал недавно), batch-запись на диск.

**Риск:** Для микро-сессии batch-запись 5+ файлов на диск — это overkill. Предложение Drive после 2-минутного «привет-пока» может восприниматься как навязчивое.

**Рекомендация:** Добавить в протокол: «Если сессия < 10 минут — ограничь end-of-session минимальным прощанием и обновлением Memory. Batch-запись и предложение Drive — только при содержательной сессии (≥ 10 мин или ≥ 5 сообщений).»

### Edge Case 4: Смена устройства в середине «сессии»
**Сценарий:** Пользователь начал разговор на телефоне, закрыл вкладку, открыл Claude на ноутбуке.

**Найдено:** Этот сценарий эквивалентен «новый чат». Если Drive подключён — Hot_Cache даст контекст. Если только Memory — Memory работает на уровне аккаунта Claude.ai и доступна с любого устройства. **Покрытие адекватное.**

**Риск:** Минимальный. Потенциально Memory может синхронизироваться с задержкой между устройствами, но это platform limitation.

**Статус:** ✅ Покрыто.

### Edge Case 5: Пользователь отключает Drive в середине сессии
**Сценарий:** Сессия идёт, Drive был доступен в начале, но пользователь отозвал доступ в настройках Google во время диалога.

**Найдено:** Graceful Degradation (строки 286–292) покрывает «Drive временно недоступен», но не специфицирует, что делать, если Drive отключился **после** начала сессии. CLAUDE.md говорит «Не писать на диск в середине сессии», так что отключение в середине не критично. Однако если пользователь явно попросил «сохрани на диск» в середине — будет ошибка.

**Риск:** Низкий, т.к. запись на диск происходит только в конце сессии.

**Статус:** ⏳ Частично покрыто.
