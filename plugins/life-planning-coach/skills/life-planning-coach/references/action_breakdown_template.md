# Action Breakdown Template

> **When to use:** Пользователь имеет WOOP-действие и готов приступить к выполнению. Только для конкретных, пошаговых целей. Опционально: сферы Карьеры, Финансов, Здоровья, Дома, Обучения.
> **Duration:** 5–10 минут
> **Integration:** Stage 3 (WOOP) → Execution. Связь с `references/habit_loop.md` (повторяющиеся шаги → привычки), Calendar (time blocks), Energy Scheduling.

---

## Core Principle

Абстрактные намерения не работают. Конкретные, проверяемые шаги — работают.

> «Если вы не можете измерить это, вы не можете этим управлять.» (Peter Drucker)

Задача — превратить намерение в цепочку действий, где каждый шаг имеет чёткий критерий завершения.

---

## 1. Breakdown Protocol

### Step 1: Определить финишную черту

Что значит «готово»? Критерий — наблюдаемый и проверяемый.

- ❌ «Начать проект» → ✅ «Открыть документ и написать заголовок»
- ❌ «Подготовиться» → ✅ «3 вопроса с ответами на странице»
- ❌ «Разобраться» → ✅ «Список из 5 пунктов в заметках»

### Step 2: Разбить на подшаги

Каждый подшаг:
- Занимает ≤30 минут, ИЛИ
- Имеет чёткий бинарный исход (сделано / не сделано)

Если шаг больше 30 минут или неоднозначен — разбить дальше.

### Step 3: Добавить чекпоинты

Каждому шагу — критерий проверки. Ответ только «да» или «нет».

```
Шаг: [действие]
Чекпоинт: ✓ [проверяемый критерий]
```

Пример: «Написать введение» → ✓ «3 абзаца на странице, сохранено в документ»

### Step 4: Оценить время

Реалистичная оценка + буфер 20–50% (planning fallacy).

| Оценка | Буфер | Итого |
|--------|-------|-------|
| 20 мин | +5 мин | 25 мин |
| 1 час | +20 мин | 1 ч 20 мин |
| 2 часа | +40 мин | 2 ч 40 мин |

### Step 5: Определить первый шаг

Самое маленькое действие, которое можно сделать прямо сейчас.

- Не «написать отчёт» → «открыть документ и написать заголовок»
- Не «позвонить клиенту» → «найти номер в контактах»
- Не «убрать квартиру» → «взять 1 вещь и положить на место»

---

## 2. Checkpoint Format

```
Шаг: [конкретное действие]
Чекпоинт: ✓ [наблюдаемый, проверяемый критерий]

Примеры:
- «Собрать документы» → ✓ «Все 5 PDF в одной папке, название проверено»
- «Написать письмо» → ✓ «Текст открыт в редакторе, тема и приветствие написаны»
- «Сделать зарядку» → ✓ «10 приседаний выполнены, пульс зафиксирован»
```

---

## 3. Connection to Habit Loop

Шаги, которые повторяются регулярно, можно превратить в привычки через `references/habit_loop.md`:

| Условие | Что можно сделать |
|---------|-------------------|
| Шаг повторяется ≥3 раза в неделю | Рассмотреть habit stacking |
| Шаг занимает ≤2 минут | Оставить как триггер-рутину |
| Контекст стабилен (время/место) | Привязать к cue |

## Example

**WOOP-действие:** «Подготовить презентацию для работы»

| # | Шаг | Время | Чекпоинт ✓ |
|---|-----|-------|------------|
| 1 | Открыть шаблон, сохранить под новым именем | 5 мин | ✓ Файл создан, имя содержит дату и тему |
| 2 | Написать структуру: 3 основных пункта | 10 мин | ✓ 3 пункта в комментариях к слайдам |
| 3 | Собрать данные для 1-го пункта (графики/цифры) | 20 мин | ✓ Скриншоты/таблицы в папке проекта |
| 4 | Оформить титульный и 3 контентных слайда | 30 мин | ✓ Все слайды содержат заголовок и ≥1 элемента контента |
| 5 | Проверить орфографию и согласовать с коллегой | 15 мин | ✓ Отправлено на ревью, получено подтверждение |

**Первый шаг прямо сейчас:** открыть шаблон и сохранить файл.

## When NOT to use

- Творческие/исследовательские задачи (написание художественного текста, brainstorming)
- Задачи, требующие когнитивной гибкости (стратегическое планирование)
- Пользователь в стадии precontemplation или кризисе
- Пользователь явно говорит: «Я просто хочу попробовать, а не планировать каждый шаг»

---

## Quick Reference Checklist

```
□ Финишная черта наблюдаема?
□ Каждый шаг ≤30 мин или бинарен?
□ У каждого шага есть чекпоинт ✓?
□ Время оценено с буфером?
□ Первый шаг — меньше, чем кажется?
□ Повторяющиеся шаги → habit loop?
```
