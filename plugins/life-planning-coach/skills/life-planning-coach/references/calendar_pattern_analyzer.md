# Calendar Pattern Analyzer

> **Integration:** Uses Google Calendar MCP (read-only: `list_events` only).
> **Runtime:** Claude.ai + Kimi Code CLI.
> **Not supported:** Grok (native connectors), Kimi OK Computer (text-only).

---

## Read-Only Protocol

Этот модуль работает исключительно в режиме **read-only**.

- Разрешён только инструмент `list_events` — получение списка событий за выбранный период.
- **Не используются:** `create_event`, `delete_event`, `update_event`.
- Никакие данные календаря не изменяются и не записываются.

---

## Security & Permissions

Перед каждым анализом — явное согласие пользователя:

> «Проанализирую ваш календарь за последнюю неделю?»

- Анализ возможен только при наличии подключённого MCP-коннектора.
- Пользователь может отказаться — и это нормально.
- Данные событий не кэшируются между сессиями.

## Metrics

| Metric | Formula | Threshold | Conversational Insight |
|--------|---------|-----------|------------------------|
| Meeting Load % | meeting hours / work hours × 100 | Risk >50%, Severe >65% | «X% дня во встречах — выше рекомендуемого 50%» |
| Focus Time | work hours − meeting hours | Deficit <3.5h | «Сегодня только X часов на фокус — стоит ли защитить блок?» |
| Boundary Violation | events after shutdown or weekends | Any = flag | «На этой неделе X событий после 18:00» |
| Recovery Deficit | back-to-back without 15-min gap | >2 in a row = warning | «X встреч подряд без перерыва — добавить буфер?» |
| Chronotype Alignment | deep work in peak hours / total deep work | <50% = mismatch | «Y% аналитики запланировано после обеда — перенести на утро?» |

**Рабочие часы:** настраиваются пользователем (по умолчанию 9:00–18:00). Пиковые часы для глубокой работы определяются через диалог, а не жёстко заданы.

---

## Weekly Trends

Для выявления устойчивых паттернов требуется **минимум 3 недели** данных.

- 1 неделя — снимок, без трендов.
- 2 недели — первое сравнение, осторожные наблюдения.
- 3+ недели — можно говорить о паттернах: «Третья неделя подряд Meeting Load выше 50% — интересно, что происходит?»

---

## Anti-Patterns (What NOT to Do)

- Не выдавать «продуктивный скор» или рейтинг — это создаёт тревожность.
- Не сравнивать с другими пользователями.
- Не переносить встречи автоматически без явного разрешения.
- Не навязывать «оптимальное расписание» — хронотипы разные, и это нормально.

---

## Rate Limits

- По умолчанию: **1 анализ в неделю**.
- Можно увеличить частоту, если захотите, но рекомендуется не чаще — иначе рискуем видеть шум вместо паттернов.
- Пользователь всегда может запросить анализ вне расписания — это не блокируется.
