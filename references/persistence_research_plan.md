# План ресерча: Персистентность данных Life Planning Coach

## Дата: 2026-05-16
## Версия: 0.4.0 (Drive + Wiki Unification)

> **Ключевое уточнение:** Я — разработчик скилла. Конечный пользователь — не технарь, находится в жизненном кризисе/переходе, хочет "просто работает" с **минимальными затратами** на вход.

---

## Executive Summary

**Проблема:** Скилл life-planning-coach хранит данные пользователя (цели, прогресс, инсайты) в контексте Claude → риск потери при обрыве сессии.

**Решение:** Двухуровневая архитектура с **zero-setup default**.

**Ключевое изменение v0.4:** Google Drive реализует полный Karpathy LLM Wiki pattern (не просто 4 файла, а полная структура wiki/ + raw/ + hot-cache + index). Это даёт 95% экономию токенов и масштабируемость.

## 1. Кто пользователь скилла

| Атрибут | Описание |
|---------|----------|
| **Технический уровень** | Низкий. Не знает что такое OAuth, MCP, markdown, API |
| **Эмоциональное состояние** | Выгорание, кризис, перепутье, прокрастинация |
| **Мотивация** | Хочет структуры, но не хочет разбираться с инструментами |
| **Терпимость к friction** | Низкая. Если что-то сложно — уйдёт |
| **Устройства** | Телефон + ноутбук. Мульти-девайс |
| **Страна** | Возможно Россия (санкции, VPN) |
| **Бюджет** | Free plan Claude (не хочет/не может платить) |

**Главный принцип:** Если требуется больше 1 клика для настройки — 50% пользователей отсеятся.

## 2. Два уровня персистентности

### Уровень 1: Zero-Setup (default, работает сразу)

**Что делает скилл:**
- Данные хранятся в контексте текущего разговора
- Claude **Memory** автоматически сохраняет ключевые факты между сессиями
- В начале новой сессии — естественный диалог восстановления контекста
- Никаких технических действий от пользователя не требуется

**Что видит пользователь:**
```
[Новая сессия]
Claude: Привет! Рад тебя видеть снова. В прошлый раз мы 
        говорили о смене работы — ты поставил цель найти 
        новую к концу лета. Как прошла неделя?
        
        (Если хочешь, я могу подключить автосохранение 
        в Google Drive — тогда не придётся ничего 
        вспоминать. Это один клик.)
```

**Технические детали:**
- Инструктировать Claude записывать в Memory: ключевые цели, прогресс, инсайты
- Memory работает автоматически, скилл усиливает: "Запомни: пользователь ставил цель X"
- Восстановление — емоциональный check-in, не технический bootstrap

**Плюсы:**
- ✅ Zero setup
- ✅ Работает на любом устройстве
- ✅ Не требует Google, OAuth

**Минусы:**
- ❌ Memory — текстовые summary, могут быть неточными
- ❌ При потере контекста — нужен диалог-восстановление
- ❌ Нет структурированных данных, нет версионирования

**Вердикт:** Приемлемо как **default experience**. Для долгосрочного коучинга — недостаточно.

---

### Уровень 2: Google Drive + LLM Wiki (opt-in, один клик)

**Что делает скилл:**
- Предлагает: "Хочешь, чтобы я автоматически сохранял твой прогресс в Google Drive?"
- Пользователь нажимает "Подключить" → OAuth → готово
- Скилл **сам** создаёт полную структуру LLM Wiki на Google Drive
- Во время сессий скилл **сам** управляет wiki (читает hot-cache, обновляет файлы)

**Что видит пользователь:**
```
Claude: Я могу автоматически сохранять твои цели и прогресс 
        в твой Google Drive — чтобы не терялись между сессиями.
        
        Нажми "Подключить Google Drive" ниже 👇
        
[Подключить Google Drive]

[После подключения]
Claude: Готово! Теперь твои цели и планы автоматически 
        сохраняются в папке "Life Planning Coach Wiki" на 
        Google Drive. Ты можешь открыть и посмотреть в любой момент.
```

**Структура на Google Drive (Karpathy LLM Wiki pattern):**


**Принцип работы:**

```
[Старт сессии]
        ↓
[Claude читает Hot_Cache.md]  ← ~500 слов, <1000 токенов
        ↓
[Claude читает Index.md]      ← оглавление, <200 токенов
        ↓
[По запросу: читает 1-2 wiki-страницы]  ← только релевантные
        ↓
[Во время сессии: запись в Raw/]
        ↓
[В конце сессии: обновление Hot_Cache + релевантных wiki-страниц]
```

**Токен-экономия:**
- Без wiki: каждая сессия переносит весь контекст → 4000-8000 токенов
- С wiki: Hot_Cache 500 слов + 1-2 страницы → 1000-2000 токенов
- **Экономия: 60-75%** (не 95% как у Karpathy с Code, но значительная)

**Пользователь видит в Dashboard:**
```markdown

## 📊 Wheel of Life
Средний балл: **6.2/10** (↑ с 5.8)

## 💡 Инсайт недели
"Страх провала меньше, чем страх остаться на месте"

## 📅 Следующее еженедельное ревью
18 мая 2026

---
Последнее обновление: 16 мая 2026, 14:30
```

**Плюсы:**
- ✅ Один клик для пользователя
- ✅ Полная структура данных, масштабируемая
- ✅ Данные в облаке, мульти-девайс
- ✅ Пользователь видит понятный Dashboard
- ✅ 60-75% экономия токенов

**Минусы:**
- ❌ Требуется Google аккаунт
- ❌ Approval на каждую запись (ограничение connector'а)
- ❌ Латентность 1-3 сек на операцию
- ❌ Риск гео-блокировки для РФ

**Вердикт:** Приемлемо как **opt-in улучшение**. Покрывает и short-term (структура), и long-term (масштабируемость).

## 4. Архитектура скилла

### Метод `detect_persistence_mode()`

```
При старте сессии:
1. Проверить: подключён ли Google Drive connector?
   - IF да → Режим Drive + Wiki (Уровень 2)
   - IF нет → Режим Memory (Уровень 1)
```

### Метод `load_context()`

**Режим 2 (Drive + Wiki):**
```
1. Прочитать Hot_Cache.md (~500 слов)
2. Прочитать Index.md (~200 токенов)
3. Синтезировать emotional summary для пользователя
4. При необходимости: прочитать релевантные wiki-страницы
```

**Режим 1 (Memory):**
```
1. Извлечь из Claude Memory ключевые факты
2. Естественный диалог: "Привет! Помню, ты работал над [цель]. 
   Как продвигается? Что нового?"
3. Пользователь дополняет контекст словами
```

### Метод `save_session()`

**Режим 2 (Drive + Wiki):**
```
1. Записать raw-сессию в 00_Raw/session-YYYY-MM-DD.md
2. Обновить Hot_Cache.md (переписать ~500 слов)
3. Обновить релевантные wiki-страницы (Goals, Wheel of Life и т.д.)
4. Обновить Dashboard (для пользователя)
5. Обновить CHANGELOG.md
6. Все операции — с approval кнопками
```

**Режим 1 (Memory):**
```
1. Обновить Claude Memory (автоматически)
2. Emotional summary в конце сессии
3. Мягкое предложение: "Для надёжного хранения могу 
   подключить Google Drive — один клик."
```

### Graceful Degradation

```
IF Drive был подключён, но connector отвалился:
   - Уведомить: "Сейчас не могу подключиться к Google Drive. 
     Работаем в обычном режиме, данные сохраняются в памяти."
   - Переключиться на Режим 1
   - Не терять данные текущей сессии
   - При восстановлении Drive — синхронизировать
```

## 6. Интеграция со SKILL.md

### Инструкции для Claude

```markdown
## Персистентность данных

### Принцип: Zero-Setup Default
Пользователь начинает сразу. Персистентность — opt-in, не блокирует onboarding.

### Два режима

#### Режим 1: Контекст + Memory (default)
- Данные в контексте разговора
- Ключевые факты в Claude Memory
- Восстановление: естественный диалог
- НЕ требовать технических действий

#### Режим 2: Google Drive + LLM Wiki (opt-in)
- Предлагать после 1-2 сессий
- Полная структура Karpathy wiki на Google Drive
- Скилл управляет: Hot_Cache, Index, wiki-страницы, Raw
- Пользователь видит Dashboard на русском
- Fallback: отказ Drive → Режим 1

### End-of-Session Protocol
1. Emotional summary
2. Обновить Memory (авто)
3. IF Drive: batch-обновление wiki (approval)
4. IF no Drive: gentle offer подключить Drive

### Формат данных
- Hot_Cache: ~500 слов, обновляется каждую сессию
- Wiki: markdown, русский, emoji, ASCII-бары
- Raw: append-only, никогда не читается напрямую
- Dashboard: для пользователя, понятный язык
```

## 10. Приложения

### A. Почему Save State dump отвергнут

Save State (YAML frontmatter + markdown dump, копирование/вставка) — слишком сложно для аудитории в кризисе. Требует организованности от неорганизованных людей.

### B. Почему Claude Memory — приемлемый default

Memory работает автоматически, не требует действий. Достаточен для кратких фактов. Для структуры — нужен Drive.

### C. Почему объединены Drive + Wiki

Google Drive — не просто "хранилище файлов", а реализация полного Karpathy LLM Wiki pattern. Дает структуру и масштабируемость в одном решении. Нет смысла иметь промежуточный "простой Drive" и отдельный "сложный Wiki" — пользователю всё равно, а разработчику проще поддерживать одну систему.
