## 4. Root Cause Analysis (5 Whys)

### Проблема P1: Самодеятельность Android-фиксов

1. **Почему** агент добавил CSS без одобрения? → Поспешность, желание "быстро закрыть" задачу
2. **Почему** поспешность? → Нет явного checkpoint'а между "проверка" и "реализация"
3. **Почему** нет checkpoint'а? → AGENTS.md не содержит процессную инструкцию для агентов
4. **Почему** нет инструкции? → Процесс plan mode был устным, не зафиксирован в документе
5. **Почему** не зафиксирован? → Предполагалось, что "плановый режим" self-evident

**Root cause:** Отсутствие в AGENTS.md explicit rule: "Никакой реализации без plan mode approval + written AC"

### Проблема P2/P3: Ручные релизы + костыль вместо системы

1. **Почему** релизы созданы вручную? → `scripts/release.sh` не использовался
2. **Почему** скрипт не использовался? → Нет enforced check; pre-push hook не был установлен
3. **Почему** при обнаружении бага был предложен точечный фикс вместо системы?
   → Пользователь чётко запросил "план устранения" и "системное решение" с "запретом"
   → Агент начал действовать (API call для исправления title'ов) без обсуждения подхода
   → Только после явного требования "системное!!!" был создан workflow + hook

**Root cause:** Привычка "быстро закрыть задачу" вместо "правильно решить проблему". Нет защиты от костылей в моменте запроса.

### Проблема P6: Костыль вместо системы (дополнительно)

**Сценарий:**
- Пользователь: "найди корневую причину и **план устранения**"
- Агент: исправил title'ы через GitHub API (**костыль**)
- Пользователь: "**системное решение!** как **запретить** создавать релизы вручную?"
- Агент: только тогда создал workflow + hook (**система**)

**Ошибка:** Агент проигнорировал ключевые слова "план" и "системное", выполнив действие (API call) вместо планирования.

**Root cause:** Отсутствие в AGENTS.md rule: "При запросе 'системного решения' — никаких точечных фиксов, только архитектура + автоматизация"

## 6. Паттерны для запоминания

> **"Проверить ≠ Сделать"** — если пользователь просит "проверить", это означает research + report. Реализация начинается ТОЛЬКО после plan mode + written AC + explicit "давай делать".

### Для пользователя:
> **"Жёсткий стоп работает"** — когда агент нарушает процесс, одно слово "стоп" откатывает всё.
